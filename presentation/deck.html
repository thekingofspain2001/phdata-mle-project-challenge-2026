Listings with blanks get turned away

Problem

A seller's listing is missing the bathroom count or the plot size. The API rejects the whole request. No price comes back.

Impact

Up to 10–20% of live requests stall. The agent phones back, the seller waits, the valuation queue stops.

Cost

Every rejected listing is a conversation restarted and a deal delayed. Coverage, not accuracy, is what leaks.

Average Value

Add all twelve sizes, divide by twelve. One city-wide number fills every blank. Simple; ignores the house.

Mean value

Sort the row, take the middle. Mansions stop skewing the answer. Still one number for all blanks.

Nearest Neighbor

Take the 5 nearest sizes; closer homes count more. Each blank gets its own answer from its own street.

Summary: which value to fill

Average and middle give every blank one city-wide number. Similar homes answer per street — and on the fields that move price, that measures 8–21% closer.

What the test actually showed

How it was tested

21,613 sales, 15% of every numeric field blanked at random, zipcode held back. Mean, median and NN(5) distance-weighted each refilled the blanks; error measured against the values we hid. 17 fields, one seed.

Read honestly: KNN wins the size and grade fields it was chosen for, and loses overall. It ships because those are the fields that move price — not because it won the experiment.

Faster answers

Before

Every request reloaded the model, the maps and the comparables from disk. The handler was async, so that work ran on the event loop and blocked every other request behind it.

After

Artifacts load once at startup and stay in memory — no file I/O per request. The handler is now plain def, which FastAPI runs in its worker threadpool instead of on the event loop, so one slow prediction no longer stalls the rest.

Measured

Over the 100 unseen examples: typical 36 ms down to 9 ms. Slow tail 48 ms down to 14 ms.

Serial, single client, one machine. Under 8 concurrent callers both slow down: the work is CPU-bound, so threads do not add throughput.

Errors you can act on

Before

A mistyped area code blows up. The agent sees a dead end and starts over.

After

A plain-words reply names the bad code. Fix the digit, move on.

HomeFeaturesV2 object

Input features for home price prediction v2; non-zipcode fields nullable.

bedrooms (integer | null)

sqft_living (number | null)
sqft_lot (number | null)
floors (number | null)

Same eight fields. Swagger now demands one instead of eight, and every optional field still carries its bounds check.
